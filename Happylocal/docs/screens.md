# 화면 설계서

두 개의 웹 앱입니다.

| | 주소 | 대상 | 폭 |
|---|---|---|---|
| **여행자 앱** | `/happylocal_v2.html` | 일반 사용자 | 420px 폰 |
| **운영 화면** | `/admin.html` | 농가 · 매장 · 지자체 | 반응형 (사이드바 ↔ 상단탭) |

나눈 이유는 세 가지입니다. 여행자 앱은 폰 목업 디자인 언어로 6,300줄이 짜여
있고, 관리자 코드를 넣으면 일반 사용자에게도 배포되며, 운영 화면은 매장
카운터의 태블릿에서 쓰입니다. **로그인 세션(쿠키)은 공유하므로 계정은 하나**
입니다.

---

## 1. 여행자 앱

### 1.1 구조

```
탭바 (하단 5개)
├── 홈        s-home       세일 상품
├── 로컬루트   s-route      코스 추천
├── 캘린더     s-cal        제철 · 축제
├── 내 코스    s-mycourse   저장한 코스 · 예약
└── MY        s-my         계정 · 설정

앱바 (상단)
├── 지도      s-map
└── 장바구니   s-cart       (배지: 대기 중 예약 수)
```

전환은 `.screen.active` 클래스 하나로 합니다. 히스토리는 `goBack()` 이
직접 관리합니다 (브라우저 뒤로가기와 별개).

### 1.2 화면 명세

#### `s-home` — 홈

| | |
|---|---|
| **목적** | 지금 예약할 수 있는 지역 세일 상품을 보여준다 |
| **진입** | 앱 시작 · 탭바 |
| **주요 요소** | 히어로 배너(자동 넘김) · 지역 칩 3개 · 정렬 토글 · 상품 카드 목록 · 더 보기 |
| **데이터** | `PL[]` (부트스트랩) — `fid` `name` `prod` `was` `now` `stock` `soldOut` `tag` |
| **상태** | 로딩 / 목록 / 빈 목록("이 지역에 예약 가능한 세일이 아직 없어요") |
| **규칙** | 목록은 보유 상품 수만큼만 표시한다 (예전에는 순환 반복했다) |
| **나가기** | 카드 → `s-store-detail` · 지도 버튼 → `s-map` |

#### `s-map` — 지도

| | |
|---|---|
| **목적** | 지역별 매장과 축제를 **한 화면에서** 본다 |
| **주요 요소** | 카카오맵 · 지역 FAB · 카테고리 칩 · 마커(픽업/관광/맛집/축제) · 하단 목록 시트 |
| **데이터** | `PLACES` `GEO` `MAP_PDAY` `CAT_MATCH` |
| **상태** | 지도 로딩 / 표시 / **키 없음 → Leaflet+OSM 폴백** |
| **규칙** | 카카오 JS 키가 없거나 도메인 미등록이면 자동 폴백. 지도가 안 뜨는 상태를 만들지 않는다 |

#### `s-route` · `s-routebuild` · `s-route-detail` — 로컬루트

| | |
|---|---|
| **목적** | IC 도착 후 픽업·관광·맛집을 묶은 하루 동선을 제안한다 |
| **요소** | 지역 선택 · 스타일 선택 · 코스 카드 · 경유지 타임라인 · 코스 담기 |
| **데이터** | `POOL[지역]` = `{ic, pk[], tour[], food[]}` → `buildCourses()` |
| **규칙** | 같은 코스를 두 번 담아도 중복 저장되지 않는다 |

#### `s-cal` · `s-seasonal` — 제철 캘린더

| | |
|---|---|
| **목적** | 언제 무엇이 제철이고 어떤 축제가 열리는지 |
| **요소** | 월 격자 · 지역 필터 · 제철 품목 바 · 축제 마커 |
| **데이터** | `cal` `CAL2_SEASONAL` `CAL2_FESTIVAL` `CAL2_TODAY` |
| **규칙** | 캘린더 축제는 **실제 개최 연도**를 쓴다 (지도 쪽은 "매년 N월"). 기준 오늘은 서버가 내려준 실제 날짜 |

#### `s-stores` — 내 주변 매장

| | |
|---|---|
| **목적** | 가까운 · 마감 임박 · 평점 높은 매장을 찾는다 |
| **요소** | 탭 3개 · 검색바(토글) · 매장 카드(재고 점 · 거리 · 주소) |
| **데이터** | `STORES` + `PLACES[key]` (`stock` `remain`) |
| **규칙** | 재고 배지와 마감임박 정렬은 **연결된 상품의 실재고**를 쓴다. 시드 문자열이 아니다 |

#### `s-store-detail` — 상품 · 매장 상세

| | |
|---|---|
| **요소** | 사진 · 이름 · 가격(정가 취소선) · 재고 · 픽업일시 · 수량 스테퍼 · 예약 버튼 |
| **규칙** | **수량 상한 = 실재고.** `+` 를 계속 눌러도 상한에서 멈추고 `−` 는 1 아래로 안 간다 |
| **날짜** | "오늘 · N월 N일 (요일)" — 실제 오늘 (예전에는 4월 12일 고정) |

#### `s-pay` — 결제

| | |
|---|---|
| **요소** | 상품 요약 · 수량 · **쿠폰 행(누르면 시트)** · 금액 내역 · 동의 · 결제 버튼 |
| **금액** | 상품금액 = 정가×수량 · 할인 = (정가−판매가)×수량 · 쿠폰 · **결제금액 = 상품금액 − 할인 − 쿠폰** |
| **규칙** | 쿠폰이 결제액보다 커도 0 아래로 안 간다. 수량이 바뀌면 쿠폰 조건을 다시 계산한다 |
| **성공** | 서버 주문 생성 → 예약코드 발급 → 재고 차감 → 예약 내역 갱신 |
| **실패** | 재고 부족 시 "현재 N개 남았어요" 안내하고 화면을 되돌린다 |

#### `cpsheet` — 쿠폰 선택 시트

| | |
|---|---|
| **요소** | 주문액 안내 · "사용 안 함" · 쿠폰 목록(할인액 · 조건 · 사용 불가 사유) |
| **규칙** | 가장 많이 깎이는 쿠폰이 기본 선택. 조건 미달 쿠폰은 **사유와 함께** 비활성 |

#### `s-cart` — 장바구니 (예약 내역)

| | |
|---|---|
| **요소** | 건수 · 예약 카드(코드 · 상품 · 금액 · 상태) · **픽업 코드 보기** · 예약 취소 |
| **규칙** | 서버가 정본이라 새로고침해도 유지된다. 배지 숫자 = 카드 수 = 건수 |

#### `pvsheet` — 픽업 코드 제시

| | |
|---|---|
| **목적** | 매장 카운터에서 코드를 보여준다 |
| **요소** | 38px 코드 · 상품·수량 · 매장·픽업일 · **노쇼 안내** |
| **왜** | 예전에는 코드가 상세 화면 작은 글씨 한 줄에만 있었다 |

#### 나머지

| 화면 | 목적 | 핵심 규칙 |
|---|---|---|
| `s-login` | 로그인 · 가입 | 카카오 + 아이디/비밀번호, 로그인/가입 모드 전환 |
| `s-mycourse` | 저장 코스 · 예약 | 탭 2개, 건수가 실제와 일치 |
| `s-my` | 계정 · 설정 | 픽업완료 수는 실제 주문 기준 |
| `s-reviews` | 내 후기 | `?mine=1` — 남의 후기가 섞이지 않는다 |
| `s-coupons` | 쿠폰함 | 계정별 |
| `s-invite` | 친구 초대 | 계정별 코드, 복사는 **링크** |
| `s-notif` | 알림 설정 | 5개 항목이 서버 키와 1:1, 계정에 저장 |
| `s-notice` `s-faq` `s-inquiry` `s-terms` `s-privacy` | 고객지원 | 운영자가 편집한 내용 |

## 2. 운영 화면 `/admin.html`

### 2.1 구조

```
┌────────────┬──────────────────────────────┐
│ 사이드바    │  본문                         │
│ 로고        │  제목 + 설명                  │
│ 내 정보     │  알림 줄 (성공/오류)           │
│  · 역할 칩  │  ────────────────────         │
│ 메뉴 (역할별)│  화면별 내용                  │
│ 로그아웃    │                              │
└────────────┴──────────────────────────────┘
```

820px 아래에서는 사이드바가 상단 가로 스크롤 탭으로 바뀝니다.

**메뉴는 `/api/auth/roles` 의 `can` 맵으로 정합니다.** 화면에서 메뉴를 숨기는
것은 편의일 뿐이고, 실제 차단은 서버가 라우트마다 합니다.

### 2.2 관문 (로그인 전)

| | |
|---|---|
| **요소** | 카카오 버튼 · 아이디/비밀번호 폼 · (로컬에서만) 개발용 역할 선택 |
| **상태** | 비로그인 → 폼 / 로그인했지만 운영 권한 없음 → **"관리자에게 역할을 요청하세요"** |
| **규칙** | 배포에서는 개발용 상자가 나오지 않는다 |

### 2.3 화면 명세

#### `pickups` — 오늘 픽업 `store_manager` **P0**

| | |
|---|---|
| **목적** | 손님이 댄 코드로 찾아 수령 확인을 찍는다 |
| **요소** | **큰 코드 입력창**(19px, 대문자, 자간 넓게) · 조회 결과 카드 · 요약 3개 · 예약 표 |
| **표 열** | 예약코드 · 상품/농가 · 수량 · 금액 · 예약자 · 상태 · 조작 |
| **정렬** | 대기 건이 위, 그 다음 최신순 |
| **조작** | 수령 확인 · 노쇼(재고 복구 여부를 확인 대화로 선택) |
| **상태** | 대기(노랑) · 수령완료(초록) · 취소(회색) · 노쇼(빨강) |
| **규칙** | 코드는 대소문자 무관. 담당 거점 것만 조회된다. 처리된 건은 버튼이 사라진다 |

> 이 화면이 **매장에서 실제로 매일 쓰이는 유일한 화면**입니다. 입력창을 크게
> 둔 것도 카운터에서 한 손으로 쓰기 때문입니다.

#### `shipping` — 오늘 출하 `producer` **P0**

| | |
|---|---|
| **목적** | 오늘 낼 물량을 넣어 앱 재고를 채운다 |
| **요소** | 재고 배지(3개 이하 빨강, 0 회색) · 상품명/농가/가격 · 수령 대기 건수 · 수량칸 · 출하 버튼 |
| **경고** | 재고 3개 이하 상품이 있으면 상단에 붉은 줄 |
| **규칙** | 담당 상품만. 출하는 재고에 **더한다**(대체가 아니다). 빼는 것은 매장 재고 조정 |

#### `closing` — 일일 마감 `store_manager`

요약 6개: 대기 · 수령완료 · 취소 · 노쇼 · **매출(수령완료 기준)** · 판매 수량.

#### `mystores` — 매장 정보 `store_manager`

거점마다 카드. 운영시간 입력 · 영업/휴무 선택 · 저장. 아래에 입점 상품 표
(상품 · 농가 · 재고 · **재고 조정** 버튼). 조정은 수량과 **사유를 모두** 받습니다.

#### `sales` — 판매 현황 `producer`

요약 6개 + 상품별 표(판매 · 매출 · 현재 재고). 매출은 수령완료 기준.

#### `mysettle` — 정산 `producer` / `settle` — 정산 집행 `super_admin`

| | |
|---|---|
| **공통** | 기간 줄(시작·종료·조회·이번 달·지난달) · 요약 4개 · 농가별 표 |
| **표 열** | 농가 · 건수 · 판매액 · 수수료 · **지급액** (집행 화면은 + 지급 버튼) |
| **기본 기간** | **이번 달** (지난달로 두면 열자마자 비어 있다) |
| **규칙** | 지급액 = 판매액 − 수수료. 쿠폰 할인은 플랫폼 부담이라 농가 몫에서 빼지 않는다. 지급은 한 번만 |

#### `content` — 콘텐츠 편집 `operator`

| | |
|---|---|
| **레이아웃** | 좌측 키 목록(20개, 크기 표시) + 우측 JSON 편집기 |
| **조작** | 저장 · 되돌리기 |
| **규칙** | 화이트리스트 밖 키는 안 열린다. JSON 오류는 저장 전에 잡는다. 통째로 비우는 저장은 서버가 막는다 |

#### `coupons` — 쿠폰 발행 `operator`

할인 · 이름 · 조건 · 유효기간 → 전체 회원 발행. **조건 문구가 곧 규칙**입니다
("최대 8,000원"=상한, "3만원 이상"=최소액, "횡성 매장"=지역). 되돌리기 어려워
확인 대화를 거칩니다.

#### `reviews` — 후기 관리 `operator`

매장·작성자 · 별점 · 내용 · 상태 · 숨기기/재노출. 숨길 때 사유를 받습니다.

#### `stats` — 전체 통계 `operator` · `super_admin`

가입자 · 상품 · 거점 · 매출 / 대기·완료·취소·노쇼 / **전체 재고 · 품절 상품** /
지역별 표. 재고 총량이 줄기만 하면 출하가 멈춘 신호입니다.

#### `apply` — 입점 심사 `super_admin`

상태 필터(대기·승인·반려·전체) · 신청 표 · 승인/반려. **승인하면 그 자리에서
역할과 범위가 붙습니다** — 승인만 하고 범위를 안 주면 로그인해도 아무것도
못 보는 상태가 되기 때문입니다.

#### `users` — 계정 · 역할 `super_admin`

계정 표(역할 칩 · 담당 범위 요약 · 상태) → 편집기(역할 다중선택 · 담당 거점
다중선택 · 담당 상품 다중선택) · 저장 · 계정 정지/해제.

#### `audit` — 감사 로그 `super_admin`

시각 · 실행자 · 행위 · 대상. 되돌리기 어려운 변경만 남깁니다
(역할 변경 · 콘텐츠 저장 · 쿠폰 발행 · 후기 조치 · 정산 지급 · 입점 심사).

## 3. 공통 규칙

### 3.1 상태 표현

| 상태 | 여행자 앱 | 운영 화면 |
|---|---|---|
| 로딩 | 스켈레톤 · "불러오는 중" | "불러오는 중…" |
| 빈 목록 | 무엇을 하면 채워지는지 안내 | `.empty` 한 줄 |
| 오류 | 토스트 | 상단 붉은 줄 (`#msg`) |
| 성공 | 토스트 | 상단 초록 줄, 3.5초 후 사라짐 |

### 3.2 되돌릴 수 없는 조작

확인 대화를 거치고, 무엇이 일어나는지 문장으로 적습니다.

- 노쇼 처리 — **재고 복구 여부까지 대화에서 고릅니다**
- 쿠폰 전체 발행
- 정산 지급 처리
- 계정 정지 · 역할 회수
- DB 초기화 (`confirm: "RESET"` 문자열 필요)

### 3.3 테마

둘 다 라이트/다크를 지원합니다. 토큰을 `:root` 에 정의하고
`prefers-color-scheme` 과 `[data-theme]` 에서 **토큰만** 다시 정의합니다.
색을 미디어쿼리 안에서만 정의하지 않습니다 — 시스템 설정이 "자동"인 경우
`data-theme` 이 아예 없어서 그 색이 적용되지 않습니다.

### 3.4 반응형

여행자 앱은 420px 고정 폭 폰 목업입니다. 운영 화면은 820px 을 경계로 사이드바가
상단 탭으로 바뀌고, 모든 표는 자기 컨테이너 안에서 가로 스크롤합니다
(본문이 좌우로 밀리지 않습니다).

### 3.5 접근성

- 아이콘 버튼에 `aria-label`
- 키보드 포커스에 눈에 보이는 테두리 (`:focus-visible`)
- 숫자 열에 `font-variant-numeric: tabular-nums`
- 예약코드처럼 읽어야 하는 값은 자간을 넓힘
